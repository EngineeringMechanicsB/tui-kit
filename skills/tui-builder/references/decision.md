# 选型：rich / textual / 纯文本

## 一张表

| | rich | textual | 纯文本 |
|---|---|---|---|
| 是什么 | 渲染库（可打印任何东西） | 应用框架（事件循环 + 布局） | 内置 print |
| 能不能 Win7 | ✅（3.8 + rich 14.0.0） | ❌（py≥3.9 且要 VT） | ✅ |
| 交互能力 | 无，靠 `input()` | 焦点/键盘/鼠标/按钮 | 无 |
| 学习成本 | 低：学会 6 个组件就够用 | 中：Widget + CSS + Worker + Screen | 零 |
| 单文件 exe 体积 | ~9 MB（py3.8 实测） | ~21 MB（py3.12 实测） | ~7 MB |
| 起步代码量 | 60–120 行 | 200–400 行 | 30 行 |
| 适合 | 运维/配置/批量脚本 | 常驻控制台、复杂面板 | 一次性小工具 |

## 实测数据（同一需求：设备列表 + 进度 + 日志）

| 实现 | 行数 | 一次跑通 | 备注 |
|---|---|---|---|
| rich（`demo_tui.py`） | ~90 | ✅ | Live 实时表格 + 进度条 |
| textual（`demo_showcase.py`） | ~470 | ✅ | 标签页/按钮/模态/主题/自适应 |
| Go bubbletea | ~140 | ✅ | 单文件 5.7 MB，但要换语言 |

bubbletea 的额外结论：v1.3.10 要求 Go 1.24，v2 要求 Go 1.26，而 Go 1.21 起不再支持
Win7；且 `tty_windows.go` 里 `SetConsoleMode` 开 VT 失败直接返回错误。
**只要目标里有 Win7，Go 这条路直接排除。**

## 判定流程

```
目标机有 Win7？
├── 有 → rich（Python 3.8）
│        └── 需要按钮/鼠标/全屏？→ 放弃，改用 rich + input() 菜单
└── 没有 → 需要全屏、键盘导航、多面板？
          ├── 需要 → textual
          └── 不需要 → rich（体积小一半，代码少一半）
```

## 什么时候值得上 textual

- 工具有 3 个以上"页面"/面板，且要反复切换
- 需要长时间停留在界面上（监控、轮询、看板）
- 有明确按钮语义（开始/暂停/重置），且希望鼠标也能点
- 会有人长时间盯着看 → 主题、间距、层级带来的观感提升才值钱

## 什么时候不值

- 一条命令跑完就退出（批量配置、烧写、导出报告）→ rich 足够
- 要拷给生产部门在裸 Win7 上双击 → textual 直接出局
- 逻辑本身还在一半，先把业务跑通再考虑全屏

## 混用策略（推荐）

同一个项目里：

```
run_all.py        # 业务编排，纯函数，不碰屏幕
ui_kit.py         # rich 组件（默认界面）
app_tui.py        # textual 外壳（可选，--tui 时启动）
```

业务函数只返回 `(ok, detail)`，两种界面都能套。
这样 Win7 用 exe / Win10 用 `--tui`，共享同一套逻辑。
参考 `assets/app_skeleton.py` 的 `_tick()` 与 `assets/ui_kit.py` 的 `run_steps`。

## 依赖与版本

| 场景 | 版本 |
|---|---|
| Win7 目标 | `rich==14.0.0`、Python 3.8.10、PyInstaller 5.13.2 |
| 仅 Win10/11 | 最新 `rich`、`textual>=8` 均可 |

rich 15.0.0 起要求 Python ≥3.9，**不要**在 Win7 环境升级。
textual 8.x 要求 Python ≥3.9，且实际使用需要 VT 终端（Windows Terminal）。
